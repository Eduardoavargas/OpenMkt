# OpenMkt M0 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first self-hostable OpenMkt foundation: a portable TypeScript monorepo with Hono server, React Web app, PostgreSQL/Drizzle persistence, Better Auth, Workspace tenancy, base audit infrastructure, Docker local deployment, and CI quality gates.

**Architecture:** Keep source boundaries aligned with the approved design: `apps/server` owns HTTP delivery, `apps/web` owns the browser UI, and reusable domain/infrastructure code lives in packages. Better Auth owns identity/session mechanics, while OpenMkt Core owns Workspace membership and authorization. No Google provider, MCP, Change Engine, billing, LLM-provider, or Cloud-specific implementation belongs in M0.

**Tech Stack:** Node.js 24 LTS, TypeScript strict mode, pnpm workspaces, Turborepo, Hono, React + Vite + TanStack Query, PostgreSQL, Drizzle ORM, Better Auth, Zod, Vitest, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-09-30-openmkt-architecture-design.md`

## Global Constraints

- License the OpenMkt core and first-party applications under AGPL-3.0.
- The OSS runtime must remain vendor-neutral and runnable with Node.js, PostgreSQL, and Docker-compatible infrastructure.
- `Workspace` is the primary tenancy boundary; every workspace-owned lookup must verify membership/ownership.
- Better Auth is identity infrastructure only; do not use its organization model as the OpenMkt Workspace domain.
- Use email/password auth in M0; Google/GitHub sign-in may remain optional configuration hooks but must not be required.
- Keep business/domain rules out of Hono route handlers.
- Do not add Google Ads, GA4, GTM, MCP, Change Engine, billing, LLM APIs, service accounts, configurable RBAC, or microservices in M0.
- Use ESM packages and TypeScript strict mode.
- New IDs generated by OpenMkt domain code use `crypto.randomUUID()` string UUIDs; do not require a PostgreSQL extension for ID generation.
- API errors must be structured and must not leak whether an inaccessible Workspace exists.
- All secrets remain environment-backed in M0; no secrets may be committed or logged.

## Review Focus

1. **Cross-workspace access:** an authenticated member of Workspace A requesting Workspace B by ID must receive the same `404 WORKSPACE_NOT_FOUND` shape as a nonexistent workspace; tests belong to Task 4 and Task 6.
2. **Expired/missing session:** protected endpoints must return `401 UNAUTHENTICATED` and never populate a principal; tests belong to Task 3 and Task 6.
3. **Duplicate tenancy records:** duplicate workspace slugs and duplicate `(workspaceId,userId)` memberships must be rejected by database constraints and surfaced predictably; tests belong to Task 2 and Task 4.
4. **Partial social-auth configuration:** supplying only one of client ID/client secret for an optional social provider must fail configuration validation rather than silently disabling or partially enabling it; tests belong to Task 3.
5. **Database unavailable/stale:** startup/migration failures must be explicit and CI must prove migrations can apply to an empty PostgreSQL database; tests/checks belong to Task 2, Task 8, and Task 9.

## M0 Definition of Done

M0 is complete only when all of the following are true:

1. `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:integration`, and `pnpm build` all pass.
2. Drizzle migrations apply successfully to an empty PostgreSQL database.
3. `docker compose up --build` boots PostgreSQL, server, and Web without a proprietary managed dependency.
4. A new user can sign up/sign in with email/password.
5. An authenticated user can create and list Workspaces.
6. Workspace creation creates an `owner` membership and a `workspace.created` audit event.
7. Workspace A cannot access Workspace B, and inaccessible/nonexistent workspace IDs share the same 404 response shape.
8. The Web UI supports login, workspace list/create, workspace detail shell, and audit visibility.
9. Better Auth remains identity-only; no Better Auth organization construct exists in the domain.
10. No Google/MCP/Change Engine/Cloud billing/LLM-provider code has leaked into M0.
11. CI reproduces the same quality gates on Node 24 + PostgreSQL.
12. The repository remains AGPL-3.0 and vendor-neutral.
